## English

### 1. Scope and current service status

This policy applies to the Keepit browser extension/add-on for Chromium-based browsers and Firefox-based browsers, including its Dashboard, page features, translation, dictionary, text-to-speech, Bilingual Reader, flashcards, diagnostics, and user-invoked AI-provider URL/selected-text workflow.

In version 3.5.108, Keepit does not operate an account server, cloud-sync service, remote Keepit database, or real payment service. The Dashboard's account and billing screens are local prototypes. Notes and settings are stored in the browser profile. The future cloud section below is a description of a plan, not a statement that Keepit currently collects or stores data in the cloud.

### 2. Information handled by the current extension

**Information stored in the browser profile.** Keepit stores information needed for the features you use, such as highlights, note text, quoted/context text, page title and URL associated with an annotation, colors, tags, favorites, flashcard/study data, extension settings, and local feature/cache/usage state. If you create or edit the Dashboard's demo profile, its display name, username, email address, and avatar image data (if supplied) are also stored locally; this is not a real online account. Annotation data is stored in extension IndexedDB; settings and other local state use the browser's extension storage. Keepit does not currently send this local library, demo profile, or settings to a Keepit-operated server.

**Page content.** The extension's content scripts run on supported web pages to provide highlighting, notes, translation, dictionary, and Reader features. Page text is processed in the browser to provide those features. Keepit does not currently upload whole browsing sessions to a Keepit server. When you invoke a feature that needs an outside service, the relevant word, selected text, or Reader passage may be sent to that service as described below.

**ChatGPT URL and selected-text workflow.** ChatGPT is user-invoked. On an unmapped page, `Alt+X` prepares the localized summary instruction; **Ask AI** reads only the current selection and prepares a localized question. New installs have auto-send off; an already saved explicit preference is honored. If the user opted in, only explicit Keepit actions may use ChatGPT `?q=` and auto-send. A prompt the user writes in the composer is never auto-sent by Keepit. With auto-send off, the explicit sample contains no URL; when the user sends on an exact unmapped URL, Keepit adds the localized website label and exact current URL at that moment. The same send-time URL addition applies to a user-written prompt. Keepit saves the exact URL → conversation mapping only after the message send is confirmed. For a mapped URL, Alt+X only reopens its conversation; Ask AI uses only the current selection and omits the URL. Passive source/tab changes clear stale composer text and leave the composer blank; they do not create prompts or send messages. Keepit does not save or restore composer drafts. Temporary metadata for an explicit Keepit sample can contain its selected snippet/prompt, request ID, source tab/URL, and expiry. A manual-send request for user-written text stores request/provider/window/source identifiers, mode and expiry, not the prompt text. Request metadata is removed on completion, panel close/cancel, source supersession, or expiry (the manually-sendable Keepit sample can remain pending for up to 24 hours; a user-written manual-send request expires after 2 minutes). This is operational request data, not a saved composer draft. Route-only session metadata contains the source URL and a sanitized ChatGPT route without query/hash/prompt/composer text, and is used only for the same exact source URL. The exact full source URL—including its query or fragment—is the mapping key and is sent to OpenAI only when the user submits a prompt or explicitly opted into an auto-sending Keepit action. Keepit does not extract or send the page body/main text or title, and this workflow does not use the clipboard. The conversation URL is validated and stored locally; ChatGPT handles submitted messages under OpenAI's terms and privacy policy. The current workflow has no clipboard read/write path or permission.

**Gemini and Claude AI panel workflows.** The visible provider tabs are ChatGPT, Gemini, and Claude; Grok is hidden from those tabs, though legacy Grok sign-in handling remains. With auto-send off, a Keepit-action draft does not include the source URL. At a manual Send on an unmapped source, Keepit silently adds the localized website label and exact current URL to the outgoing message; this also applies to a prompt the user typed. On a mapped source, the message is sent without the URL, as with ChatGPT. Before clicking Send, Keepit waits for the exact expected editor text to settle and rechecks it; if it cannot confirm the text, it does not send or save a mapping. The shared auto-send preference defaults off for new installs and honors a previously saved explicit preference. If enabled, only explicit Keepit actions may auto-send; a user-written prompt is never auto-sent. Ask AI's draft begins with only the current selection. On an exact mapped URL, Keepit reopens that provider conversation. In Chromium, the embedded provider page tells the Keepit panel only its sanitized conversation route (no query, hash, prompt, or composer text) so the panel can switch conversations; this stays inside the browser. Mapping is stored locally only after the send is confirmed. Request metadata for a Keepit action can temporarily contain its prompt/selection and source identifiers; a manual-send request for user-written text stores only request/source identifiers and expiry, not the prompt. Keepit does not read, save, or restore composer drafts, page body/title, or clipboard content. Each provider handles sent messages under its own terms and privacy policy.

**Legacy Grok sign-in handling.** Grok is hidden from the visible AI provider tabs; the existing Chromium frame/ancestor-origin validation remains in the code for the legacy panel flow. If invoked, it opens Grok's standard start page (`https://grok.com/`) in a top-level tab. The extension passes only origins to its own background component for validation; it does not pass an OAuth URL, read sign-in fields, or access credentials, tokens, or cookies. If you choose Google sign-in, you enter information directly into the browser's top-level sign-in page and Google handles it under Google's own terms. Keepit temporarily stores the opened tab ID, browser window ID, and a short cooldown in session storage to avoid duplicate tabs. Keepit does not close the new tab or expose the former Grok toolbar fallback. Firefox behavior is unchanged.

**Speaking practice audio.** When you start Dictation Speaking mode, the browser's SpeechRecognition feature processes speech to produce a transcript; the browser/provider may process the audio under its own settings and privacy terms. Keepit also records a temporary audio clip in memory solely to play back your own voice. Keepit does not write that clip to extension storage or a file, and does not upload it. The temporary recording/Blob URL is released when the attempt is reset, the sentence or mode changes, or the panel closes.

**Local usage prototype.** Current usage-limit and billing logic is a local prototype. Its counters and prototype state are stored in the browser profile; the current build does not send those counters to a Keepit billing server and does not process real payments.

**Diagnostic error log.** Keepit stores up to 200 classified technical entries in browser extension storage. Each entry contains a timestamp, component, severity, and category code. It does not store the original console message, stack trace, page URL, page contents, selected text, or account details. The log is not automatically uploaded to Keepit. A JSON file is created only when you explicitly choose **Export log** in Dashboard > Settings > About and is then handled by your browser as a download.

### 4. Storage, retention, export, and deletion

Local extension data remains in the browser profile until it is deleted through the extension/browser controls or removed by the browser. You can export supported library data from the Dashboard and delete annotations/pages using the available Dashboard controls. Export important data before uninstalling or clearing browser extension data; exact removal behavior depends on the browser.

Session-only extension storage keeps panel toggle state and the selected visible AI provider ID per window so state can survive background-worker restarts. This metadata contains no composer text and is not sent to Keepit or an AI provider. The local diagnostic log is capped at 200 entries; when new entries exceed that limit, older entries are dropped. It is not currently automatically uploaded, and the current UI provides export but not a dedicated clear-log button. Temporary translation/dictionary caches are stored locally to avoid repeat requests and are managed by the extension's cache behavior. Exact source URL → conversation mappings for ChatGPT, Gemini, and Claude are stored locally after a send is confirmed. Session-only route metadata contains a source URL and a sanitized ChatGPT route without query/hash/prompt/composer text; it is used only when reopening the same source. Explicit Keepit prompt/selection data may be held in temporary request metadata and cleared on completion, close/cancel, source supersession, or expiry. For a manually sent user-written prompt, Keepit stores request/provider/window/source identifiers, mode and expiry, not the prompt text. With auto-send explicitly enabled, explicit Keepit actions may submit on ChatGPT, Gemini, or Claude; ChatGPT may use its `?q=` URL, while Gemini/Claude use the provider workflow. Keepit does not store per-source composer drafts.

Keepit cannot delete information retained by an outside provider after you have sent a request to that provider. To exercise controls over provider-held data, contact that provider under its own privacy process.

### 5. Permissions and access

The Chromium manifest requests permissions for storage, larger local storage, active-tab/tab functions, the Side Panel API, network-request rules, and the `contextMenus` permission for the user-invoked selected-text Ask AI menu shared by Chromium and Firefox. It does not request clipboard permissions. The Firefox build removes the Chromium-only `sidePanel` permission/`side_panel` key and uses Firefox's native `sidebar_action` with `open_at_install: false` instead. Content scripts are configured to run on supported websites because highlighting, notes, translation, Reader, and the user-invoked AI-provider workflow needs access to the current page URL and, only when Ask AI is clicked, the user's selection. Host access also supports the named translation, dictionary, font, favicon, and registered AI-provider sites. In Chrome, a narrowly scoped network rule removes `X-Frame-Options` and `Content-Security-Policy` response headers only for subframes on the registered AI-provider host allowlist; this weakens those protections for those framed provider documents. Firefox opens the selected provider as a top-level page in its native sidebar. These permissions do not mean that Keepit sends every page to a Keepit server; the transmissions described above occur only for specific user-invoked features. The policy and any in-product disclosures must remain consistent with the actual manifest and behavior. Speaking auto-record is enabled by default: after the current cue's final repeat ends and the video pauses, it may request microphone access after a two-second delay. Auto-started recognition uses a single utterance and ends according to the browser's speech endpoint. The user can disable the toggle and use manual Enter/microphone controls instead; browser permission settings still govern access. Keepit's short recording is held in memory for playback and is not persisted or uploaded by Keepit; browser speech recognition may process audio through its configured provider.

### 6. Security and international processing

Current user-created content and settings are stored in the browser profile; Keepit does not currently maintain a cloud copy. Keepit does not add its own encryption layer to browser-profile storage. Protect your device and browser profile, and use the browser's security controls. Requests to the listed HTTPS services are handled by those providers, which may process them in countries other than yours under their own terms.

## Tiếng Việt

### 1. Phạm vi và trạng thái hiện tại

Chính sách này áp dụng cho tiện ích Keepit trên các trình duyệt nhân Chromium và Firefox, gồm Dashboard, tính năng trên trang, dịch, từ điển, chuyển văn bản thành giọng nói, Bilingual Reader, flashcard, nhật ký chẩn đoán và luồng AI provider URL/văn bản đã chọn do người dùng chủ động gọi.

Trong phiên bản 3.5.108, Keepit chưa vận hành máy chủ tài khoản, dịch vụ đồng bộ cloud, cơ sở dữ liệu Keepit từ xa hoặc thanh toán thật. Các màn hình tài khoản và thanh toán trong Dashboard chỉ là bản mẫu local. Ghi chú và cài đặt được lưu trong hồ sơ trình duyệt. Phần cloud bên dưới chỉ mô tả kế hoạch, không có nghĩa Keepit đang thu thập/lưu dữ liệu cloud.

### 2. Thông tin được xử lý trong bản hiện tại

**Thông tin lưu trong hồ sơ trình duyệt.** Keepit lưu dữ liệu cần cho tính năng bạn sử dụng, ví dụ phần tô sáng, nội dung ghi chú, câu trích/ngữ cảnh, tiêu đề và URL trang gắn với ghi chú, màu, tag, mục yêu thích, dữ liệu flashcard/ôn tập, cài đặt extension và trạng thái cache/sử dụng local. Nếu bạn tạo hoặc sửa hồ sơ demo trong Dashboard, tên hiển thị, username, email và dữ liệu ảnh đại diện (nếu có) cũng được lưu local; đây không phải tài khoản trực tuyến thật. Dữ liệu annotation lưu trong IndexedDB của extension; cài đặt và trạng thái local khác dùng bộ nhớ extension của trình duyệt. Hiện Keepit không gửi thư viện local, hồ sơ demo hoặc cài đặt đến máy chủ do Keepit vận hành.

**Nội dung trang.** Content script chạy trên website được hỗ trợ để cung cấp tô sáng, ghi chú, dịch, từ điển và Reader. Nội dung trang được xử lý trong trình duyệt để cung cấp các tính năng đó. Hiện Keepit không tải toàn bộ lịch sử duyệt web lên máy chủ Keepit. Khi bạn dùng tính năng cần dịch vụ bên ngoài, từ/câu/đoạn liên quan có thể được gửi đến dịch vụ đó như mô tả bên dưới.

**Luồng ChatGPT dùng URL và văn bản đã chọn.** ChatGPT do người dùng chủ động gọi. Prompt do người dùng tự viết trong composer không bao giờ được Keepit auto-send. Metadata bị xóa khi hoàn tất, đóng/hủy panel, source khác thay thế hoặc hết hạn (sample Keepit có thể chờ gửi tối đa 24 giờ; request manual-send của prompt người dùng hết hạn sau 2 phút). **Gemini và Claude trong AI panel.** Tab hiển thị gồm ChatGPT, Gemini và Claude; Grok bị ẩn khỏi tabs nhưng legacy sign-in handler vẫn còn. Khi auto-send tắt, draft từ action Keepit không chứa URL. **Âm thanh khi luyện nói.** Tự động ghi âm Speaking mặc định bật: sau khi cue cuối (kể cả repeat) kết thúc và video tạm dừng, Keepit đợi 2 giây rồi có thể yêu cầu quyền microphone. Lượt tự động dùng nhận diện một câu và kết thúc theo endpoint của trình duyệt. Bạn có thể tắt công tắc để dùng Enter/mic thủ công; quyền truy cập vẫn do trình duyệt quyết định. SpeechRecognition xử lý lời nói để tạo transcript; trình duyệt/nhà cung cấp có thể xử lý audio theo cài đặt và chính sách riêng. Keepit chỉ giữ bản ghi tạm trong bộ nhớ để phát lại, không ghi vào extension storage/tệp và không upload. Bản ghi/Blob URL được giải phóng khi đặt lại lượt luyện, đổi câu/chế độ hoặc đóng panel.

**Bản mẫu hạn mức local.** Logic hạn mức và billing hiện tại là bản mẫu chạy local. Bộ đếm và trạng thái mẫu được lưu trong hồ sơ trình duyệt; bản hiện tại không gửi số liệu này đến máy chủ billing của Keepit và không xử lý thanh toán thật.

**Nhật ký lỗi local.** Keepit lưu tối đa 200 mục kỹ thuật đã phân loại trong bộ nhớ extension. Mỗi mục chỉ có thời điểm, thành phần, mức độ và mã loại lỗi. Log không lưu nguyên văn thông báo console, stack trace, URL trang, nội dung trang, text đã chọn hoặc thông tin tài khoản. Log không tự động được tải lên Keepit. Chỉ tạo file JSON khi bạn chủ động bấm **Export log** trong Dashboard > Settings > About; trình duyệt sẽ xử lý file đó như một lượt tải xuống.

### 4. Lưu trữ, thời hạn, export và xóa

Dữ liệu extension local tiếp tục nằm trong hồ sơ trình duyệt cho đến khi bạn xóa bằng tính năng của extension/trình duyệt hoặc dữ liệu bị trình duyệt xóa. Bạn có thể export dữ liệu thư viện được hỗ trợ từ Dashboard và xóa annotation/trang bằng các điều khiển hiện có. Hãy export dữ liệu quan trọng trước khi gỡ extension hoặc xóa dữ liệu extension trong trình duyệt; cách xóa chính xác phụ thuộc trình duyệt.

Extension storage theo phiên lưu trạng thái panel và ID provider đang hiển thị đã chọn theo từng cửa sổ để khôi phục sau khi background worker khởi động lại. Metadata này không chứa composer text và không gửi tới Keepit hay provider AI. Nhật ký lỗi local giới hạn ở 200 mục; khi vượt giới hạn, mục cũ bị loại bỏ. Hiện log không tự động được upload; giao diện có chức năng export nhưng chưa có nút xóa log riêng. Cache dịch/từ điển tạm thời được lưu local để giảm request lặp và được quản lý theo cơ chế cache của extension. Mapping exact source URL → conversation cho ChatGPT, Gemini và Claude được lưu local sau khi xác nhận tin nhắn đã gửi. Metadata route theo phiên chỉ chứa URL nguồn và route ChatGPT đã bỏ query/hash/prompt/composer text, chỉ dùng khi mở lại cùng source. Selection/prompt của action Keepit có thể được giữ trong request metadata tạm và bị xóa khi hoàn tất, đóng/hủy, source khác thay thế hoặc hết hạn. Với prompt người dùng tự viết, Keepit chỉ lưu ID request/provider/window/source, mode và thời hạn, không lưu nội dung prompt. Khi bật auto-send rõ ràng, chỉ action Keepit explicit có thể gửi trên ChatGPT, Gemini hoặc Claude; ChatGPT có thể dùng URL `?q=`, còn Gemini/Claude dùng provider workflow. Keepit không lưu composer draft theo từng source URL.

Keepit không thể xóa dữ liệu mà nhà cung cấp bên ngoài đã lưu sau khi nhận request. Muốn thực hiện quyền kiểm soát dữ liệu do nhà cung cấp giữ, bạn cần liên hệ với nhà cung cấp đó theo quy trình riêng của họ.

### 5. Quyền và truy cập

Manifest Chromium yêu cầu quyền cho bộ nhớ, dung lượng local mở rộng, tab đang hoạt động/các thao tác tab, Side Panel API, quy tắc request mạng và quyền `contextMenus` cho menu Hỏi AI selection do người dùng gọi trên Chromium/Firefox; manifest không yêu cầu quyền clipboard. Firefox build bỏ permission `sidePanel`/key `side_panel` chỉ dành cho Chromium và dùng `sidebar_action` tích hợp của Firefox với `open_at_install: false`. Content script chạy trên website được hỗ trợ vì các tính năng tô sáng, ghi chú, dịch, Reader và luồng AI provider do người dùng gọi cần URL hiện tại; riêng khi bấm Hỏi AI, content script chỉ lấy đoạn người dùng đang chọn. Quyền host cũng phục vụ các dịch vụ dịch, từ điển, font, favicon và AI provider đã đăng ký. Trên Chrome, quy tắc mạng chỉ gỡ `X-Frame-Options` và `Content-Security-Policy` cho subframe thuộc allowlist host AI provider đã đăng ký; việc này làm yếu các bảo vệ đó trong tài liệu provider được nhúng. Firefox mở provider đã chọn ở cấp cao nhất trong sidebar tích hợp. Các quyền này không có nghĩa Keepit gửi mọi trang đến máy chủ Keepit; dữ liệu chỉ được truyền cho tính năng cụ thể do người dùng chủ động gọi như mô tả ở trên. Chính sách và mọi thông báo trong ứng dụng phải khớp với manifest và hành vi thật. Tự động ghi âm Luyện nói mặc định bật; sau cue cuối/repeat và khi video tạm dừng, Keepit có thể yêu cầu quyền microphone sau 2 giây. Lượt tự động kết thúc theo endpoint một lượt của trình duyệt. Người dùng có thể tắt công tắc để dùng Enter/mic thủ công; quyền truy cập do trình duyệt quyết định. Bản ghi ngắn chỉ nằm trong bộ nhớ để phát lại, không lưu bền vững hoặc upload; nhận diện giọng nói của trình duyệt có thể xử lý audio qua nhà cung cấp được cấu hình.

### 6. Bảo mật và xử lý quốc tế

Nội dung người dùng và cài đặt hiện lưu trong hồ sơ trình duyệt; Keepit chưa giữ bản sao cloud. Keepit không tự thêm lớp mã hóa riêng cho dữ liệu trong bộ nhớ hồ sơ trình duyệt. Hãy bảo vệ thiết bị và hồ sơ trình duyệt bằng các cơ chế bảo mật của trình duyệt. Request đến dịch vụ HTTPS bên ngoài được xử lý bởi nhà cung cấp đó và có thể được xử lý tại quốc gia khác theo điều khoản của họ.

### 7. Tài khoản và cloud dự kiến — CHƯA HOẠT ĐỘNG

Phần này chỉ mô tả kế hoạch sản phẩm. Các hoạt động tài khoản/cloud dưới đây **chưa hoạt động trong phiên bản 3.5.108**. Trước khi bật, Keepit sẽ cập nhật chính sách, xác nhận nhà cung cấp/vị trí dữ liệu, giải thích dữ liệu ngay trong sản phẩm và triển khai các kiểm soát/đồng ý cần thiết.

Nếu ra mắt, tài khoản/cloud dự kiến xử lý thông tin tài khoản/định danh, annotation và cài đặt người dùng chọn đồng bộ, tiến độ flashcard/Dictation, trạng thái sync và quyền lợi/hạn mức gói. Nhà cung cấp server chưa được chọn cuối cùng. Kế hoạch hiện tại là dùng thử Ultra 7 ngày có sync; sau đó Free không tạo sync mới và dữ liệu cloud đã có chuyển sang chỉ đọc/xuất. Hạn mức gói và nhà cung cấp thanh toán còn chưa chốt. Kế hoạch cũng dự kiến gửi nhắc trước 30 và 7 ngày khi dữ liệu cloud dần bị xóa sau 12 tháng không có hoạt động có ý nghĩa, đồng thời cho phép export. Đây là quy tắc dự kiến, không phải thực hành xử lý dữ liệu hiện tại, và có thể thay đổi trước khi ra mắt.
